# تقرير اختبار الأداء — المرحلة 1 (تشخيص فقط)

المواصفة: `prompt-performance-audit.md`. التاريخ: 2026-11-11.
**لم يُعدَّل أي كود للتطبيق ولا `.env` ولا `php.ini` ولا إعدادات Apache/MariaDB/النفق الحيّة.** كل قياس يمر عبر التطبيق جرى على نسخة `dawak_perf`.
اللقطات والأدوات المؤقتة في `C:\perf-audit\` (خارج المستودع).

## 1) الخلاصة التنفيذية

**أين يذهب الوقت؟** التقسيم أدناه لتنقّل عادي بين صفحات خفيفة (مثال: «رفع المبيعات»، 83KB HTML) مع Cache دافئ بالمتصفح. هو مركّب من ثلاثة قياسات منفصلة، لا من قياس واحد شامل عبر النفق (السبب بالقسم 6):

| الجزء | الزمن المقيس | النسبة التقريبية |
|---|---|---|
| الخادم (`artisan serve` بلا OPcache) | ~500ms، منها ~470ms إقلاع Laravel وترجمة PHP، و~25ms عمل الصفحة الفعلي | ~40% |
| النفق Cloudflare | ~290ms وسيط زمن أول بايت لملف ثابت صغير (مقابل 6ms محلياً) | ~25% |
| المتصفح (CSS/JS/خطوط من CDN خارجي + Tailwind بالمتصفح) | ~420ms بعد أول بايت حتى `load` | ~35% |
| **المجموع** | **~1.2 ثانية لكل نقرة** | |
| قاعدة البيانات | 4 استعلامات ثابتة ≈ 3ms بكل طلب | <1% |

**بالصفحات الثقيلة والتقارير:** الخادم يطغى على كل شيء. تقرير «دوران المخزون» يأخذ 10–12 ثانية ويولّد **37.9MB HTML**. «قيمة المخزون» يأخذ 3–5 ثوانٍ وفيه 22,160 عنصر DOM.
**وفوق ذلك:** الخادم أحادي المعالجة، فأي طلب ثقيل **يجمّد كل المستخدمين** طوال مدته.

**أهم 5 أسباب (مرتبة بالأثر المقيس):**
1. **`php artisan serve` أحادي المعالجة على Windows.** 8 طلبات متزامنة تُخدم واحداً تلو الآخر (من 0.5 إلى 3.9 ثانية). وصفحة خفيفة أُرسلت أثناء تقرير ثقيل انتظرت **11.5 ثانية** بدل 0.5. وتعدد العمّال غير مدعوم: ظهرت الرسالة `forking is not supported on this platform`. **هذا هو التفسير المقيس لـ«البطء عند أي تصدير حتى بالتنقل».**
2. **OPcache غير محمَّل إطلاقاً** (لا للـCLI ولا لـApache): كل طلب يترجم ملفات Laravel كلها من جديد.
   - بتفعيله: الصفحة الخفيفة **494ms ← 60ms (−88%)**.
   - ومع Apache وكاش الإعدادات: **← 40ms**.
3. **صفحات تقارير ترسم كل البيانات بلا ترقيم:**
   - «دوران المخزون»: 12.4 ثانية، 37.9MB، ذروة ذاكرة 125MB.
   - «قيمة المخزون»: 4.6 ثوانٍ، 3.9MB.
   - «المناقلات العكسية»: 2.6 ثانية. «قيمة المناقلات»: 2.6 ثانية.
   - زمن الاستعلامات فيها كلها < 0.7 ثانية: **الوقت يذهب بـPHP (حساب + رسم Blade)، لا بالقاعدة.**
4. **الأصول الخارجية تحجب أول رسم:**
   - بـCache بارد: أول رسم بعد وصول الصفحة **666ms مع الأصول مقابل 117ms بحجبها كلها** (−550ms).
   - Tailwind عبر `cdn.tailwindcss.com` (398KB، تُترجَم بالمتصفح بكل صفحة) وحده: **~200ms** من أول رسم و~30ms تنفيذ JS بكل صفحة، رغم أنه مستعمل بـ~39 سطراً في 3 ملفات فقط.
5. **النفق:**
   - +~290ms لكل طلب (وسيط؛ حتى 806ms).
   - نفق «سريع» (`trycloudflare.com`) باتصال QUIC واحد، أُعيد فتحه 49 مرة، و51 خطأ طلب مسجّل.
   - تنقّل بين مواقع Cloudflare: لندن، طوكيو، باليرمو حالياً.

**التصدير:** أكبر تصدير ممكن من الواجهة (كل فواتير أكبر يوم: 1,764 صفاً) يأخذ ~3.4 ثانية عبر HTTP، فلا شيء يقترب من حد Cloudflare (100 ثانية). المشكلة الحقيقية أن التصدير **يجمّد الخادم** طوال مدته (السبب 1). و`ShouldAutoSize` يكلّف 40–46% من زمن التصديرات الكبيرة.

## 3) مكاسب سريعة بلا مخاطرة (أوامر دقيقة — لم يُنفَّذ أي منها)

> كلها تُنفَّذ بمهمة لاحقة بموافقة مجد. خذ نسخة احتياطية قبل كل ملف إعداد.

1. **تفعيل OPcache** — `C:\xampp\php\php.ini` (يؤثر على كل تطبيقات PHP بالجهاز وعلى Apache بعد إعادة تشغيله):
   ```ini
   zend_extension=opcache
   opcache.enable=1
   opcache.enable_cli=1          ; ضروري ما دام artisan serve مستعملاً
   opcache.memory_consumption=256
   opcache.max_accelerated_files=20000
   opcache.validate_timestamps=1 ; يُبقي تعديلات الكود فورية
   opcache.revalidate_freq=2
   ```
   ثم أعد تشغيل `artisan serve` (أو خدمة Apache). المقيس: 494 ← 60ms للصفحة الخفيفة.
   ملاحظة: ظهرت رسائل `VirtualProtect() failed [87]` بسجل Apache التجريبي مع OPcache، ولم تؤثر على النتائج.
2. **`.env`:**
   - `APP_DEBUG=false`.
   - `APP_ENV=production` اختياري: يغيّر سلوك بعض الأوامر (تطلب `--force`).
   - `LOG_LEVEL=warning`: أثره المقيس على الأداء ضئيل، لكنه سليم.
3. **كاش Laravel** — بعد كل نشر/سحب كود:
   ```
   php artisan config:cache && php artisan route:cache && php artisan event:cache && php artisan view:cache
   ```
   - **التحقق من `env()` خارج `config/`:** بحثتُ في `app/` و`routes/` و`resources/` و`bootstrap/app.php` ولم أجد أي مخالفة، فالكاش آمن.
   - **تنبيه:** بعد `config:cache` يصبح تعديل `.env` بلا أثر حتى تعيد `php artisan config:cache`.
   - **خطوة الرجوع:** `php artisan optimize:clear`.
   - المقيس: −15 إلى −20ms بكل طلب.
4. **تقديم التطبيق بـApache بدل `artisan serve`** (أكبر أثر، انظر الخطوات أدناه).
5. **استثناء Defender** (قرار أمني لمجد): مجلد المشروع، و`C:\xampp\php`، و`C:\xampp\mysql\data`. **لم يُقَس أثره.**
6. **MariaDB** (`C:\xampp\mysql\bin\my.ini`): `innodb_buffer_pool_size=256M`. **لم يُقَس أثره.** يحتاج إعادة تشغيل الخدمة، وهي مشتركة مع التطبيقات الأخرى.

### خطوات الانتقال إلى Apache (للتنفيذ لاحقاً بموافقة مجد)

Apache 2.4.58 مثبّت مع XAMPP ويعمل **كخدمة تلقائية** (`Apache2.4`، Automatic) على 8080/443، بـ`mpm_winnt` و`ThreadsPerChild 150`. القياس تمّ على **نسخة Apache منفصلة** بإعداداتها الخاصة (انظر القسم 6)، أما الخطوات أدناه فتضيف منفذاً للخدمة الحيّة نفسها:

1. **نسخ احتياطي:**
   - `C:\xampp\apache\conf\httpd.conf`
   - `C:\xampp\apache\conf\extra\httpd-vhosts.conf`
   - `C:\xampp\php\php.ini`
2. **فعّل OPcache** بـ`php.ini` (البند 1 أعلاه).
3. **أضف بآخر `httpd-vhosts.conf`:**
   ```apache
   Listen 127.0.0.1:8081
   <VirtualHost 127.0.0.1:8081>
       ServerName dawak.local
       DocumentRoot "C:/Users/Administrator/Desktop/dawak-project-develop/public"
       <Directory "C:/Users/Administrator/Desktop/dawak-project-develop/public">
           Options -Indexes +FollowSymLinks
           AllowOverride All
           Require all granted
       </Directory>
       ErrorLog "logs/dawak-error.log"
       CustomLog "logs/dawak-access.log" common
   </VirtualHost>
   ```
   (`mod_rewrite` محمَّل أصلاً بـ`httpd.conf`.)
4. **`php artisan config:cache` إلزامي هنا، لا اختياري:** PHP داخل Apache على Windows يعمل بنسخة متعددة الخيوط (ZTS)، و`putenv` مشترك بين خيوط العملية. فإن خدم Apache نفسه تطبيقات Laravel أخرى قد تتداخل قيم `.env` بينها. كاش الإعدادات يمنع قراءة `.env` وقت الطلب.
5. **تحقق قبل إعادة التشغيل:** `C:\xampp\apache\bin\httpd.exe -t`، ثم أعد تشغيل خدمة Apache من XAMPP Control Panel. تنبيه: ينقطع 8080/443 ثوانٍ قليلة.
6. **اختبر محلياً** `http://127.0.0.1:8081` (دخول، فاتورة، تصدير).
7. **وجّه النفق:** أوقف نافذة `cloudflared tunnel --url http://127.0.0.1:8013` وشغّل `C:\cloudflared\cloudflared.exe tunnel --url http://127.0.0.1:8081`.
   - تنبيه: النفق السريع يغيّر الرابط عند كل إعادة تشغيل. النفق المسمّى (البند 6 بالجدول) يحل ذلك.
   - لتشغيل `cloudflared` تلقائياً مع الإقلاع يلزم نفق مسمّى: `cloudflared service install`.
8. **الرجوع:** أعد النفق إلى 8013. `artisan serve --port=8013` يمكن إبقاؤه يعمل بالتوازي طوال التجربة، ونسخ الملفات الاحتياطية تعيد Apache كما كان.

## 4) تعديلات كود مقترحة (لا تُنفَّذ الآن)

1. **التقارير** (`inventory.reports.*`) — الأولوية الأولى:
   - ترقيم أو تجميع بالخادم بدل رسم كل الصفوف. «دوران المخزون» يرسم 37.9MB.
   - دمج N+1:
     - `max(updated_at) ... where pharmacy_id=?` ×12 ← استعلام واحد `group by pharmacy_id`.
     - أسعار `central_inventory_prices` بدفعات ×11/×18 ← استعلام واحد مجمّع لكل التقرير.
   - التحقق قبل التحسين: تحليل أين تذهب ثوانيه بـPHP (حساب أم رسم) — لم يُقَس بأداة profiling بهذه المرحلة.

   ```php
   // database/migrations/xxxx_add_perf_indexes.php — اقتراح، لم يُنشأ
   Schema::table('pharmacy_inventories', fn (Blueprint $t) => $t->index(['quantity']));               // where quantity > 0 = مسح كامل (20,475 صفاً، ~54ms)
   Schema::table('pharmacy_inventories', fn (Blueprint $t) => $t->index(['pharmacy_id', 'updated_at'])); // max(updated_at) لكل صيدلية
   Schema::table('invoices', fn (Blueprint $t) => $t->index(['status', 'date']));                     // تقارير الدوران: filesort + temporary اليوم
   ```
   - `audit_logs`: لا يلزم الآن (الاستعلام يستعمل فهرس `action`).
   - `central_inventory_prices`: فهرس `(product_id, effective_from)` موجود. لكن `date(effective_from) <= ?` تمنع استعمال الجزء الثاني منه؛ الأفضل `effective_from < ?+1day`.
4. **الأصول:**
   - Tailwind CDN ← CSS ثابت بالأصناف المستعملة فقط (~39 سطراً بها `tw-*` في `layouts/admin.blade.php` و`components/stat-card.blade.php` و`components/file-upload-zone.blade.php`).

   - المقيس: −550ms لأول رسم بـCache بارد عند حجب الكل.
5. **التصدير:**
   - `WithColumnWidths` بدل `ShouldAutoSize` بـ`AllInvoicesExport` و`ShortagesExport` و`InvoiceExport` و`ReverseTransferExport` (−30 إلى −46%).

   - النقل للطابور غير ضروري لحد Cloudflare حالياً (أطول تصدير ممكن من الواجهة ~3.4 ثانية). الأهم ألّا يحجب الخادم (يحله Apache).
6. **الجلسات والكاش:** إبقاء `database` (الأثر المقيس ~3ms/طلب).

```

```

- العروض المترجمة والسجل تُكتب بمجلد مؤقت لا بـ`storage/` التطبيق.
- طلبات داخلية عبر `Kernel::handle()` بجلسة حقيقية (صف `sessions` + كوكي مشفّر)، فتُحسب استعلامات الجلسة/المستخدم/الصلاحيات كالإنتاج.

- التصدير يُقاس من كلاسات `app/Exports` مباشرة (`Excel::raw`)، لا مسارات التصدير التي تقفل الفواتير.

**ما أطلبه من مجد** (شبكة المستخدمين لا تُقاس من السيرفر):
1. افتح التطبيق عبر الرابط من جهاز موظف عادي بـChrome، واضغط `F12` ← تبويب **Network**، وفعّل **Disable cache**.
2. حدّث الصفحة (`Ctrl+R`) بصفحة «رفع المبيعات» ثم بصفحة «تفاصيل فاتورة مناقلة».
3. رتّب العمود **Time** تنازلياً وصوّر أبطأ 10 سطور، مع السطر الأخير بالأسفل (`requests / transferred / Finish / DOMContentLoaded / Load`).
4. أعد نفس الشيء **بعد إلغاء** Disable cache (تنقّل عادي).
5. أرسل الصور مع اسم المدينة/مزوّد الإنترنت للجهاز.

## 6) ما لم يُقَس ولماذا، والافتراضات والقرارات

**لم يُقَس:**
- **القراءة المباشرة من القاعدة الحيّة:** منعها نظام الأذونات. أُخذت النسخة بـ`mysqldump --single-transaction` (22MB) واستُوردت إلى `dawak_perf`. **التحقق من التطابق** تمّ بإعادة تفريغ `dawak_perf` ومقارنة أسطر `INSERT` كلها: 52 = 52، وبصمة SHA-256 متطابقة. ولم أقارن عدد الصفوف بالحيّة مباشرة (نفس المنع).
